# 식단표 원본 → foodbox JSON

저장소 루트에서 “이소도시락 이번 달 식단표 원본을 받아 운영 JSON까지 만들어 줘” 같은 요청에 사용한다.
원본만 요청하면 이미지 확보·확인까지만 수행한다. 스킬의 실제 파일은 이 폴더 한 곳이며,
다른 도구의 검색 경로는 이 폴더를 가리킨다. 루트 `AGENTS.md`의 역할 분담을 유지한다.

## 진행 브리핑

작업 시작에 아래 6단계와 현재 위치를 짧게 보여 준다. 각 단계 전환과 긴 작업 중 약 60초마다
현재 결과·남은 작업·막힌 이유를 알린다. 내부 추론이나 원시 프로세스 데이터는 보고하지 않는다.

| 단계 | 확인할 결과 |
| --- | --- |
| 1/6 대상 확인 | 요청 연월, 원본/JSON 범위, 출력 폴더 |
| 2/6 원본 확보 | 대상 배경 원본, 파일 크기·해상도·SHA-256 |
| 3/6 메뉴 추출 | 이미지의 모든 날짜·셀과 항목 순서 전사 |
| 4/6 JSON 생성 | 운영 스키마 후보 파일, 필요시 기존 DB와 병합 후보 |
| 5/6 대조·검증 | 원본 재대조, 날짜·누락·유효성·운영 스키마 검사 |
| 6/6 전달 | 원본·JSON 경로, 날짜 범위·건수, 검증 결과 |

브리핑 예시: `▰▰▱▱▱▱ [2/6] 원본 확보 중 · 완료: 대상 확인 · 다음: 날짜별 메뉴 추출`
막대는 **현재 단계 위치**이며 완료율 추정치가 아니다. 재시도·대기 중에는 현재 단계를 유지하고,
증거가 없는 항목을 완료 처리하지 않는다. 완료 때는 `▰▰▰▰▰▰ [6/6] 전달 완료`로 마무리한다.

## 실행 절차

1. **대상 확인.** “이번 달”은 Asia/Seoul 현재 연월로 해석한다. 명시한 연월과 앞선 대화가 있으면
   그것을 따른다. 작업 산출물은 저장소 밖 새 폴더에 모은다. 이미지가 요청한 달과 다르면 확인한
   실제 월을 먼저 알리고 의도를 해결한다. 다음 달 이미지가 먼저 올라왔다고 현재 월로 바꾸지 않는다.
2. **원본 확보.** [원본 수집 절차](references/image-source.md)를 읽고 기존 로컬 앱의 대상 프로필을
   연다. 프로필 사진 보기 창은 프로세스를 찾는 용도다. 사진과 배경이 다를 수 있으므로 추출 대상은
   `backgroundImage.originalUrl`이다. 직접 조작할 수 있으면 진행하고, 필요한 접근이 없을 때만
   사용자에게 해당 조작을 요청한다.

   ```bash
   python3 .agents/skills/foodbox-menu/scripts/menu_image.py discover
   python3 .agents/skills/foodbox-menu/scripts/menu_image.py download --candidate 1 --output '/작업폴더/source.jpg'
   ```

   받은 이미지를 실제로 보고 제목·월·요일·일반식/샐러드를 확인한다. 후보가 복수이거나
   `partial-response`인 경우에도 다운로드 성공만으로 최신 원본이라고 확정하지 않는다.
3. **메뉴 추출.** [운영 JSON 규약](references/menu-json.md)을 읽는다. 이미지를 열어 표를 행·열로
   읽고, 필요하면 기존 이미지 보기 도구로 확대한다. 원본 바이트는 유지한다. 날짜별로 위에서 아래의
   메뉴 순서를 보존해 `transcription.json`을 만든다. OCR이 이미 준비되어 있으면 초안으로 사용할 수
   있지만 원본과 대조한다. 외부 유료 OCR 호출이나 비밀 설정 탐색은 기본 절차에 필요하지 않다.
   판독 불가 셀은 추측하지 않고 별도 메모에 남겨 해결한다. 표 제목·공통 고지·중복 안내는 메뉴로 넣지 않고
   `source-notes.md`에 보존한다. 실제 음식을 나타내는 셀의 테마명은 메뉴에 유지한다.
   같은 셀의 실메뉴는 원문 철자·구두점을 임의 교정하지 않는다.
4. **JSON 생성.** 도구로 운영용 후보를 새 파일로 만든다. `--month`는 실제 확인한 표의 연월이다.
   표에 다음 달 첫 주가 함께 인쇄되면 전사에서 보존하고 `--include-following-month`를 지정한다.

   ```bash
   python3 .agents/skills/foodbox-menu/scripts/menu_json.py build --input '/작업폴더/transcription.json' --month YYYY-MM --include-following-month --source-image '/작업폴더/source.jpg' --output '/작업폴더/menu.json'
   ```

   `menu.json`은 새 날짜의 패치이며 기존 이력을 모두 담은 DB 대체본이 아니다. 기존 DB 사본을
   제공받았거나 현재 요청에서 읽을 수 있으면 아래 명령으로 별도 병합 후보를 만든다. 실제 운영
   `db/db.json`을 출력 경로로 쓰지 않는다.

   ```bash
   python3 .agents/skills/foodbox-menu/scripts/menu_json.py merge --base '/기존DB사본/db.json' --patch '/작업폴더/menu.json' --output '/작업폴더/db.merged.json'
   ```
5. **대조·검증.** 원본의 모든 셀을 다시 대조한다. 가능하면 다른 에이전트에게 이미지와 산출물만 주고
   독립 대조하게 한다. 11월 표의 12월처럼 인쇄된 범위를 누락하지 않았는지, 휴무·메뉴 순서·중복·빈 문자열을
   확인한다. 연도가 없으면 요청 연월과 날짜·요일의 일치로 검증하고 아직 애매하면 확정하지 않는다.

   ```bash
   python3 .agents/skills/foodbox-menu/scripts/menu_json.py validate --input '/작업폴더/menu.json' --month YYYY-MM --include-following-month
   ```

   병합 후보는 `validate --input '/작업폴더/db.merged.json' --legacy`로 전체 형식을 확인한다.
   JSON 구조 검사는 이미지 판독 정확성의 증명이 아니므로 결과에 두 검증을 구분해 기록한다.
6. **전달.** 원본·전사·운영 JSON·필요시 병합 후보·대조 메모의 경로를 전달한다. 요청 월, 실제 날짜 범위,
   총 일수, 유효/휴무 일수, 다음 달 포함 여부와 미해결 항목을 보고한다. 생성만 요청받은 작업은 이 단계에서
   끝난다. 실제 반영까지 요청받았다면 기존 운영 문서와 세션 권한에 따라 백업·검증을 진행한다.

## 운영 경계

- `date`는 `[year,month,day]`, `menus`는 원문 순서 문자열 배열, `valid`는 새 레코드에서 메뉴 3개 이상일 때만 true다.
- 원본·후보 목록·전사·JSON·임시 실행 파일은 Git에 넣지 않는다. 원시 메모리는 파일로 만들지 않는다.
- 생성 요청을 운영 DB 쓰기, 배포, 알림 전송으로 확대하지 않는다. `metadata.json`의 이미지 해시는 임의 갱신하지 않는다.
- 이 원본 수집 경로는 기존 게시판 크롤러와 다르다. `CRAWL_URL`을 이미지 주소로 교체하지 않는다.
- 환경·호출 안내와 도구 검증은 [운영 JSON 규약](references/menu-json.md)의 마지막 부분을 참조한다.
