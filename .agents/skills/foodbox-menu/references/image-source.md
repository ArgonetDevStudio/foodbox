# 프로필 배경에서 식단표 원본 받기

이 참조는 공통 스킬의 원본 확보 단계를 설명한다. 전체 원본→운영 JSON 절차와 진행 브리핑은
[SKILL.md](../SKILL.md)를 따른다.
기존에는 https://eisodosirak.itpage.kr/ 에서 식단표를 받았다. 2026-10-30 사용자 제공
운영 상황에 따르면 해당 사이트의 서비스가 중지되어, 이소도시락 프로필의 배경 이미지
원본을 대체 수집 경로로 사용한다. 위 주소는 기존 출처 기록이며, 도구가 현재 이미지
출처로 자동 접속하거나 운영 크롤러 설정을 바꾸지는 않는다.

Foodbox 루트에서 에이전트에게 **“이소도시락 프사에서 이번 달 메뉴 사진 원본 좀 구해줘”**라고
요청하면 아래 순서를 따르면 된다. 운영 크롤러·OCR·DB·알림에는 연결하지 않는다.

## 원본 확보 세부 순서

1. 요청한 월을 확인한다. 별도 지정이 없으면 Asia/Seoul의 현재 연·월을 기준으로 한다.
   평소 쓰는 데스크톱 앱의 이소도시락 프로필을 열고, 프로필 사진을 클릭해 **사진 보기 창**도 연다.
   기본 도구는 제목이 `이소도시락`인 창에서 Windows 프로세스 ID를 구한다.
   직접 조작 가능한 환경이면 에이전트가 진행하고, 필요한 접근이 없을 때만 사용자에게 이 단계를 요청한다.
2. 저장소 루트에서 다음 명령으로 배경 원본 주소 후보를 찾는다.

   ```bash
   python3 .agents/skills/foodbox-menu/scripts/menu_image.py discover
   ```

   기본 대상은 `userId=282181357`, `nickname=이소도시락`이다. 임의로 바꾸지 않는다.
   출력에는 `candidates`와 각 후보의 실제 `url`, `evidence`, 그리고 `manifest` 경로가 있다.
   후보 순서는 1부터 센다. 주소는 월마다 바뀔 수 있으므로 문서에 고정해 두지 않는다.
   후보 목록은 기본적으로 `~/.cache/foodbox/menu-original/candidates.json`에 권한 0600으로
   저장되며 원시 메모리는 저장하지 않는다. 이 파일은 로컬 실행 산출물이며 Git에 넣지 않는다.
3. 찾은 후보 번호를 명시해 새 파일명으로 내려받는다. 다음 예시는 첫 번째 후보다.

   ```bash
   python3 .agents/skills/foodbox-menu/scripts/menu_image.py download \
     --candidate 1 \
     --output '/home/shane/Downloads/이소도시락_식단표_원본_새파일.jpg'
   xdg-open '/home/shane/Downloads/이소도시락_식단표_원본_새파일.jpg'
   ```

   명령은 방금 발견한 로컬 후보 목록의 URL만 사용한다. 임의 URL을 직접 전달하는 옵션은 없다.
   후보가 여러 개면 번호와 출력 파일명을 바꾸어 비교한다. 기존 파일은 덮어쓰지 않는다.
4. **제목의 월, 날짜·요일, 일반식/샐러드 구분, 프로필 배경과 같은 내용인지** 눈으로 확인한다.
   이 단계가 끝나기 전에는 “이번 달 원본을 찾았다”고 확정하지 않는다. 프로필에는 다음 달
   이미지가 먼저 올라올 수도 있다. 요청한 달과 다르면 실제 확인된 월을 명확히 알려 준다.
5. 확인된 파일 경로·해상도를 사용자에게 전달한다. 바이트 수와 SHA-256도 명령 출력으로
   확인할 수 있다. 다운로드 파일을 요청 없이 운영 서비스에 등록하거나 배포하지 않는다.

**프로필 사진과 배경은 다를 수 있다.** 2026-10-30에는 사진 보기 창에 `10월 샐러드 식단표`가
열렸지만, 요청한 `11월 식단표`는 프로필 배경이었다. 사진 보기 창은 대상 프로세스를 찾는
용도이며, 추출 대상은 항상 `backgroundImage.originalUrl`이다.

이미 열린 다른 창을 사용하려면 실제 실행 중인 창 제목을 실행 시에만 전달할 수 있다.
앱 이름이나 고정 제목을 소스에 추가할 필요는 없다. 같은 제목이 서로 다른 프로세스에
있으면 도구가 거부한다. Linux PID를 Windows 프로세스 ID로 간주하지 않는다.

```bash
python3 .agents/skills/foodbox-menu/scripts/menu_image.py discover --window-title '현재 열려 있는 정확한 창 제목'
```

후보 파일 위치를 바꿀 때는 두 명령에 같은 `--manifest '/로컬/후보파일.json'`을 지정한다.
후보 파일을 편집하거나 출처를 모르는 파일로 교체하지 않는다. 실제 네트워크 호스트는
발견한 URL에 그대로 표시된다. 공급자 이름을 소스에 적지 않는 것이 주소 자체를 숨기거나
익명화한다는 의미는 아니다.

## 필요한 환경

- 이미 사용 중인 **Linux x86_64 데스크톱과 Wine** 환경을 대상으로 한다. 다른 운영체제나
  CPU용 도구가 아니다. 평소 앱과 같은 사용자·데스크톱 세션·Wine prefix에서 실행한다.
- Python 3 표준 라이브러리, `winegcc`, Wine x86_64 Unix import library가 필요하다.
  Python 패키지를 추가 설치하지 않는다. 도구가 로그인하거나 prefix를 만들지 않는다.
- 검증한 라이브러리 경로는 `/opt/wine-stable/lib/wine/x86_64-unix`다. 설치 경로가 다르면:

  ```bash
  python3 .agents/skills/foodbox-menu/scripts/menu_image.py discover \
    --wine-lib-dir '/실제/Wine/lib/wine/x86_64-unix'
  ```

## 실제로 원본을 얻은 방식

처음에는 로컬 이미지 캐시와 일반 다운로드 파일을 확인했지만, 해당 캐시는 일반 JPEG/PNG가
아닌 암호화된 형태였다. 확장자 변경으로는 열 수 없었다. **이번 방법은 캐시나 대화 DB를
복호화하는 방법이 아니다.** `/proc/<PID>/mem` 직접 읽기는 권한 오류가 났고, 관리자 권한이나
시스템 보호 설정 변경 없이 같은 Wine 환경의 Windows API 읽기로 주소를 찾았다.

```text
대상 창 찾기: EnumWindows / GetWindowTextW
  → Windows ID 얻기: GetWindowThreadProcessId
  → 읽기 권한으로 열기: OpenProcess
  → 읽기 가능한 영역: VirtualQueryEx / ReadProcessMemory
  → 대상 UTF-8 이름 및 userId·nickname 헤더 확인
  → 최상위 backgroundImage.originalUrl 후보
  → 사용자가 지정한 후보 번호의 원본을 HTTPS로 다운로드
```

프로필 응답의 구조는 다음과 같다. 주소 값은 구조 설명용이며 실행할 때마다 새로 발견한다.

```json
{
  "userId": 282181357,
  "suspended": false,
  "nickname": "이소도시락",
  "profileImage": {"originalUrl": "프로필 사진 주소"},
  "backgroundImage": {"originalUrl": "배경 원본 주소"}
}
```

UTF-16 화면 문자열 주변의 URL만 고르면 다른 이미지가 섞일 수 있었다. 실제 성공한 방법은
UTF-8 응답에서 **대상 신원과 명시적인 배경 필드의 연결**을 확인하는 것이었다. 썸네일의
쿼리를 임의로 지운 것이 아니라 앱이 받은 `originalUrl`을 그대로 사용했다.

메모리 응답 일부는 이미 재사용되어 전체 JSON 파싱이 실패했다. 대상 헤더와 배경 원본
문자열이 온전하게 남은 사본에서 주소를 찾았고, 받은 이미지를 화면과 대조했다.
도구는 전체 JSON을 읽을 수 있으면 `complete-response`, 제한된 응답 범위에서 연결된
주소만 읽었으면 `partial-response`로 표시한다. 다른 프로필 시작 경계를 넘지 않고,
중복 신원·중첩 객체·단순히 주변에 있는 URL을 거부한다. **두 표시 모두 최신 월을 자동
입증하지 않으므로 이미지 확인을 생략하지 않는다.** 앱 업데이트로 응답 구조가 바뀌면
실패할 수 있으며, 이 경우 도구와 합성 테스트를 함께 수정한다.

2026-10-30에 실제 받은 11월 파일의 검증값:

| 항목 | 값 |
| --- | --- |
| 원본 형식·해상도 | JPEG, **1080 × 1527** |
| 크기 | **343,974 bytes** |
| SHA-256 | `31a4010d0a3dca0676eebe8adb60e69d9e90edde34275f456238304bbb562199` |
| 육안 확인 | 제목 `11월 식단표`, 2일 월요일부터 시작하는 날짜표, 최초 배경과 같은 내용 |

받은 바이트를 그대로 저장했으며 확대 보정·재인코딩·OCR·이미지 생성은 하지 않았다.
위 해시는 그 파일의 재다운로드 확인용이며 다음 달 이미지가 같은 값을 가져야 하는 것은 아니다.

## 처리 범위와 파일

- [menu_image.py](../scripts/menu_image.py): 대상에 연결된 후보 발견, 권한이 제한된 로컬 후보 목록,
  명시적으로 선택한 후보의 다운로드. 실제 URL만 출력하고 관계없는 프로필·메모리 데이터는 남기지 않는다.
- [profile_scan.c](../scripts/profile_scan.c): 필요한 Windows API 선언만 가진 읽기 전용 도구다.
  대상 이름과 창 제목을 실행 인자로 받아 공급자별 이름을 하드코딩하지 않는다. 한글 인자는
  Wine 명령행 변환을 피하려고 UTF-8 바이트를 hex로 전달한다. 원시 메모리 파일을 만들지 않고,
  이름과 일치한 주변의 제한된 범위만 Python으로 파이프 전송한다. 임시 실행 파일은 자동 정리한다.
- [test_menu_image.py](../scripts/test_menu_image.py): 가상의 프로필·이미지로 검증하는 합성 테스트다.
- 프로세스 쓰기·DLL 삽입·디버거 연결·메시지 전송·앱 재시작·캐시 삭제는 하지 않는다.
- 다운로드는 발견한 후보 목록에 있는 HTTPS 원본 리소스 경로만 사용하며 인증정보·포트·쿼리·조각을
  거부한다. DNS의 모든 주소가 공인 주소인지 검사하고 검증한 주소로 연결하되 원래 호스트의 TLS
  인증서 검증은 유지한다. 리다이렉트와 사설·루프백 주소는 거부한다. 로그인 쿠키나 토큰을 보내지 않는다.
- 20초 네트워크 타임아웃, 10 MiB 제한, JPEG/PNG 헤더·해상도 확인 후 새 파일을 만든다.
  원본 이미지·후보 목록·원시 메모리·임시 실행 파일은 저장소에 넣지 않는다.
- Foodbox의 `CRAWL_URL`은 업체 게시판 URL이다. 이 절차로 찾은 이미지 주소로 바꾸지 않는다.

## 안 될 때

| 증상 | 확인할 것 |
| --- | --- |
| 빌드 실패 | 기존 `winegcc`와 x86_64 Unix 라이브러리 경로 확인. 다른 시스템용 패키지를 무작정 설치하지 않는다. |
| 대상 창 없음 | 프로필 사진 보기 창 제목이 대상 이름인지 확인하거나 `--window-title`로 이미 열린 창을 지정한다. 같은 사용자·세션·prefix여야 한다. |
| 대상 주소 없음 | 프로필을 다시 열고 잠시 기다린 뒤 재시도한다. 사본 부재·손상·응답 구조 변경 시 실패할 수 있다. |
| 후보가 여러 개 / 다른 달 | 각 후보를 다른 파일명으로 받아 실제 배경과 월·날짜·요일을 비교한다. |
| 후보 목록 없음 | 먼저 `discover`를 실행한다. 별도 경로면 두 명령의 `--manifest`가 같아야 한다. |
| HTTP 오류 / 다운로드 실패 | 이전 리소스 만료·삭제 또는 네트워크 문제를 확인하고 다시 발견한다. 토큰을 붙이거나 주소를 추측하지 않는다. |
| 기존 파일 오류 | 원래 파일을 보존하고 다른 출력 파일명을 사용한다. |

실패했다고 관리자 권한 사용, 프로세스 보호 해제, 캐시 삭제를 할 필요는 없다. 대상 신원과
연결할 수 없는 주변 URL을 대신 선택하지 않는다.

## 도구 수정 후 검증

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s .agents/skills/foodbox-menu/scripts -p test_menu_image.py -v
python3 .agents/skills/foodbox-menu/scripts/menu_image.py --help
python3 .agents/skills/foodbox-menu/scripts/menu_image.py discover
```

합성 테스트는 대상·배경 구분, 다른 프로필 경계, 손상·잘림·이스케이프된 응답, 중복 신원,
중첩 객체, 복수 후보, 후보 번호·파일 권한, DNS 주소 고정, 크기 제한, 리다이렉트 거부,
기존 파일 보존을 검사한다. 마지막 명령에는 실제로 열려 있는 대상 창이 필요하다.
